Static, versioned copies of community channel lists that Flow for Android and Flow Desktop download about once a day, and only while the matching filter is on. No accounts, no tracking, no server: just signed JSON files on a CDN.

How it works

01 · Signed

Verified before it is used

An Ed25519-signed manifest carries the SHA-256 of every file, so a compromised host or domain cannot push a fake list.

02 · Versioned

Small daily updates

Snapshots never change once published. Clients that are up to date fetch a daily delta of a few kilobytes instead of the full list.

03 · Private

Nothing to log

Requests carry no identifiers or query parameters, and the apps make none at all while the filter is off.

Overview

Every file is a static JSON document under one base URL. There are no keys, no sign-up and no write endpoints. Each list lives in its own folder, /v1/<list>/; today there is one list, aislist.

Base URL
https://ailist.flow-tube.org
Format
Minified UTF-8 JSON, no BOM, non-ASCII written raw
Auth
None
Updates
Once a day around 03:17 UTC, only when the list changed
Try it 
curl -s https://ailist.flow-tube.org/v1/index.json

Common behaviour

  • 200 with Content-Type: application/json for every published file.
  • 404 for anything that does not exist, including snapshots and deltas that have left the retention window.
  • Access-Control-Allow-Origin: * on everything under /v1/, so browsers can read it directly.
  • Responses are compressed by the CDN. Hashes in the manifest are over the uncompressed bytes.
  • Clients must ignore unknown fields. A breaking change would ship under /v2/, with /v1/ kept running.

Manifest

GET/v1/{list}/manifest.json

The only file clients poll. A signed envelope whose payload names the current version and the size and SHA-256 of every snapshot and delta still hosted.

Cache
public, max-age=3600 with an ETag
Conditional
Send If-None-Match; an unchanged manifest answers 304 with no body
Signature
Ed25519 over the exact decoded payload bytes
Envelope
{
  "key_id": "2026-11",
  "payload": "<base64 of the payload JSON bytes>",
  "sig": "<base64 of the 64-byte Ed25519 signature>"
}
Decoded payload 
{
  "schema": 1,
  "list": "aislist",
  "version": 42,
  "generated_at": "2026-11-13T03:17:00Z",
  "snapshot": { "path": "snapshot/42.json", "sha256": "<hex>", "bytes": 1094967 },
  "deltas": [
    { "to": 42, "path": "delta/42.json", "sha256": "<hex>", "bytes": 35313 },
    { "to": 41, "path": "delta/41.json", "sha256": "<hex>", "bytes": 20110 }
  ],
  "max_delta_chain": 14,
  "counts": { "block_handles": 60212, "block_ids": 0, "warn_handles": 1262, "warn_ids": 0 },
  "source": {
    "name": "AiSList",
    "homepage": "https://aisloplist.com",
    "repo": "https://github.com/Override92/AiSList",
    "commit": "<full source commit sha>",
    "license": "CC BY-NC 4.0"
  }
}
  • path Relative to the manifest's folder.
  • deltas Every delta still hosted, newest first. Version 1 has none.
  • max_delta_chain Most deltas to chain before taking the snapshot instead.

Snapshot

GET/v1/{list}/snapshot/{version}.json

The full list at one version. Never changes once published; the newest 3 are kept.

Cache
public, max-age=31536000, immutable
Size
About 1.1 MB, about 410 KB compressed
Example response 
{
  "schema": 1,
  "list": "aislist",
  "version": 42,
  "block": { "handles": ["another-one", "somechannel"], "ids": [] },
  "warn":  { "handles": ["maybechannel"], "ids": [] }
}
  • handles Normalized (see Match a channel), without @, deduplicated and sorted.
  • ids Channel IDs matching ^UC[A-Za-z0-9_-]{22}$. Empty for now; check them anyway.
  • An entry in block never also appears in warn.

Delta

GET/v1/{list}/delta/{version}.json

Changes from version - 1 to version. Never changes once published; the newest 30 are kept.

Cache
public, max-age=31536000, immutable
Size
Usually a few tens of kilobytes
Example response 
{
  "schema": 1,
  "list": "aislist",
  "from": 41,
  "to": 42,
  "block": { "handles": { "add": ["newchannel"], "remove": [] }, "ids": { "add": [], "remove": [] } },
  "warn":  { "handles": { "add": [], "remove": ["newchannel"] }, "ids": { "add": [], "remove": [] } }
}

Apply removes first, then adds, as plain set operations. Applying a delta twice is harmless.

Verify a manifest

Decode, verify, and only then parse. An unknown key_id or a failed check means: keep what you have.

Current public key, key_id 2026-11, raw 32 bytes in base64: xak9y4JaDG+UjKfl7cDwiaJs+7FjrOM+urMW1YfSuc0=
Node.js 18+ 
import { createPublicKey, verify } from 'node:crypto';

const KEYS = { '2026-11': 'xak9y4JaDG+UjKfl7cDwiaJs+7FjrOM+urMW1YfSuc0=' };
const BASE = 'https://ailist.flow-tube.org/v1/aislist/';

const envelope = await (await fetch(BASE + 'manifest.json')).json();
const raw = KEYS[envelope.key_id];
if (!raw) throw new Error('unknown key_id');

const key = createPublicKey({
  key: { kty: 'OKP', crv: 'Ed25519', x: Buffer.from(raw, 'base64').toString('base64url') },
  format: 'jwk',
});
const payload = Buffer.from(envelope.payload, 'base64');
const sig = Buffer.from(envelope.sig, 'base64');
if (!verify(null, payload, key, sig)) throw new Error('bad signature');

const manifest = JSON.parse(payload);   // parse only after verifying
console.log(manifest.version, manifest.counts);

Also refuse a manifest whose list is not the one you asked for, or whose version is lower than the one you hold.

Keep a copy current

Store the version, the ETag and the four sets. About once a day:

  1. Fetch the manifest with If-None-Match. On 304, stop.
  2. Verify it. Stop if schema is above 1, list is wrong, or version is not newer.
  3. If you hold a list, are at most max_delta_chain versions behind, and every delta in between is listed, fetch those deltas. Otherwise fetch the snapshot.
  4. Check each file's SHA-256 against the manifest before using it.
  5. Apply deltas in version order, write the result to a temporary file, then rename it into place.
  6. If a delta is missing or fails its hash, fall back to the snapshot once.

Any failure leaves the stored list exactly as it was. A failed update never clears the list.

Match a channel

A channel is listed when its normalized handle is in handles or its channel ID is in ids. Match by exact equality against a set, never by prefix: a listed @drew must not hide @drewbinsky.

Handle normalization 
function normalizeHandle(input) {
  let s = input.trim();
  const at = s.startsWith('@') ? 0 : s.indexOf('/@') + 1;
  if (s[at] === '@') s = s.slice(at + 1).split(/[/?#]/)[0];
  try { s = decodeURIComponent(s); } catch {}
  s = s.normalize('NFC').toLowerCase();
  if (!s || [...s].length > 64 || /[\s/%?#@]/.test(s)) return null;
  return s;
}

normalizeHandle('/@LinusTechTips/shorts');   // 'linustechtips'
normalizeHandle('@DPCartoon%C3%80i-v6k');    // 'dpcartoonài-v6k'
normalizeHandle('@Bad%ZZname');              // null (rejected)

Length counts code points. Kotlin and Rust ports must use locale-independent lowercasing and give the same results.
